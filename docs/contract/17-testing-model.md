# 17. Testing model (proposal)

## 17.1 Principles

1. **No real game data in the repository or in CI.** Every fixture is **synthetic**: generated by a builder at test time, tiny, and deterministic.
2. **Fakes before real tools.** Every slot is tested with fake backends. Real third-party tools get smoke tests that only run when the tool is present.
3. **Characterize v1 before changing it.** The migration must show it didn't change behavior by accident.
4. **Every contract rule has a test** that would fail if the rule broke: single writer, reserved dot-folders, routing, failover, determinism, policy refusals.
5. **Safety is tested, not assumed:** malicious archives, path traversal, pickles, game-folder restore.

## 17.2 Levels

| Level | What | Runs | Gate |
|-------|------|------|------|
| **L0 static** | formatter check; **LoC caps** (doc 15); import-direction lint (layer rule: contracts ← kernels ← plugins/backends ← core ← api/cli); every GPL/AGPL backend declares `isolation=subprocess`; every backend declares its network use; ini schema validation of `distros/*.ini` and `loc_caps.ini` | every push | blocking |
| **L1 contract / unit** | conformance kit (kernels, plugins, slots, backends) with fakes; plugin routing (`select_plugins`); ini precedence; identify/carve rules; value types; journal | every push, Linux + Windows | blocking |
| **L2 characterization** | golden files of `/api/*` payload shapes and workspace snapshots (names, sizes, hashes) for synthetic games. Captured **after the M1 hotfix**, against the *intended* behavior, with a written **intended-differences list** for each known v1 bug (H1–H3, F1, F3, F11…) | every push | blocking. Golden updates need a reason in the commit |
| **L3 component** | each plugin against its synthetic fixtures, with fake tools and stdlib backends (zip/tar, our safe RPA reader, a carved PCK) | every push | blocking |
| **L4 matrix** | (a) selection exhaustive over every plugin subset × policy (pure), plus pairwise pipeline runs (doc 3.6); (b) **slot failover**: for every slot, {main up, down} × {spare up, down} × outcome kinds (ok, unsupported, failed, needs_key, cancelled) | every push (fast fakes), Linux + Windows | blocking |
| **L5 real-tool smoke** | each real backend on its fixture: 7z, unrar, unrpa, UnityPy, AssetStudioModCLI, GDRE, GodotPckTool, repak, retoc, DataTool (CLI help/list only), ffmpeg | nightly, on CI images with the tools installed; locally when present (otherwise skipped, with a visible reason) | blocking nightly; reported per push |
| **L6 end-to-end** | CLI: `info` / `detect` / `extract` → run record → **re-run gives an identical workspace**; HTTP: v1 routes through the job adapter; **web UI smoke** with Playwright (load, extract a fixture, sort, undo, trash, merger list) | per push (CLI/HTTP), nightly (UI) | blocking |
| **L7 manual acceptance** | real games owned by the tester, run locally only, from a checklist. Results are recorded as numbers and run records, **never the assets** | at each milestone exit | sign-off |

## 17.3 Safety test catalogue (part of L1/L3)

| Test | Expectation |
|------|-------------|
| zip/tar member with `../` or an absolute path | rejected; nothing written outside dest |
| symlink inside an archive pointing outside | not followed |
| RPA whose pickled index contains a `__reduce__` payload | **no code runs**; the archive is reported as `corrupt`/`unsupported` and the spare runs only as a sandboxed subprocess |
| `.rpyc` with a pickle payload in the analysis slot | same |
| nesting depth bomb (archive in archive in archive…) | stops at the depth limit (10), reported |
| decompression bomb (huge expansion ratio) | stops at a size/ratio limit, reported ❓ limits to be defined |
| a plugin hook writes outside its staging folder | sandbox test fails (before/after file record) |
| PREPARE pointed at a folder without the workspace marker (H2) | refused, nothing deleted |
| any extraction | **game folder file hashes unchanged** before vs after (H1) |
| cross-origin `text/plain` POST, missing token, non-JSON body, foreign Host header (H3) | 403 / 415, no side effect |
| tar member with `..`, absolute path, device file, or link outside (F17) | rejected by the extraction filter |
| a capture session killed midway | the next startup finishes RESTORE; game folder hashes identical |
| a game folder with anti-cheat markers | capture refused, no launch |
| `/preview/` and `/api/*` path traversal | 404 / error, as v1 |

## 17.4 Fixtures

| Builder | Produces |
|---------|----------|
| `make_zip/tar/7z` | archives, including nested ones (7z through py7zr) |
| `make_rpa(version)` | RPA-2/3 with a safe index, plus a "malicious index" variant |
| `make_pck(version, embedded=bool, encrypted=bool)` | Godot PCK v1–v4, raw or appended to a dummy executable |
| `make_pak` | through repak itself (L5 only), or a recorded tiny pak (generated by us) |
| `make_unity_bundle` | minimal UnityFS made with UnityPy's writer (feasibility ❓); otherwise only L5 against an openly licensed sample |
| `make_game_tree(engine)` | marker-only folder layouts for every engine, including CASC markers (`.build.info`, `data/casc/`) |
| `make_mixed_folder` | several engines' markers + archives in one tree |

Fixture data is generated into a temporary folder at test time. Tiny
committed binary files are allowed only when they can't be generated, each
under 64 KB, with their origin noted.

## 17.4b Terms-of-service-sensitive cases: independent operator

Decision: tests that touch terms-of-service-sensitive targets (for example
the Overwatch plugin against a real install) are **run by an independent
operator**, never by the project's CI or maintainers.

| Aspect | Rule |
|--------|------|
| Marking | a plugin or backend whose real-data use is terms-of-service-sensitive declares `tos_sensitive: true` in its manifest |
| Project CI | runs only **fake-tool / synthetic** tests for such plugins (L1–L4). L5/L7 with real data never run in project CI |
| Operator receives | a pinned build, the plugin, a **test protocol** (checklist + commands) and the expected run-record schema |
| Operator returns | run records, metrics and pass/fail per checklist item, **never extracted assets**, plus the tool and game build versions used |
| Operator's environment | their own machine and their own licensed copy; offline flags on |
| What the operator can't do | override the framework's hard policies. Runtime capture on online/anti-cheat games stays refused for everyone |
| Records | operator reports are stored as test evidence (`docs/evidence/<plugin>/<date>.md`) without assets ❓ |

## 17.5 Tooling and environment

- **Python:** v1 uses 3.10+ syntax. Proposal: **3.11 as the minimum** (`tomllib`, better errors and `ExceptionGroup`, useful for job errors) and test **3.11 and 3.13** ❓.
- **Runner:** `pytest` as a dev-only dependency (none is installed today), with markers `l0`…`l6` and `needs_tool(<backend_id>)`. The production code stays stdlib + the declared backends.
- **CI:** GitHub Actions, `ubuntu-latest` + `windows-latest` × Python 3.11/3.13 for L0–L4 and L6-CLI. A nightly job on an image with the tools installed (pinned versions, from the vendoring decisions in doc 10) for L5 and the L6 UI.
- **Coverage floors:** `contracts/` + `core/` ≥ 90 % lines, plugins ≥ 80 %, kernels ≥ 75 % per OS (the rest is OS-specific). Floors, not targets.
- **Speed budget:** L0–L4 under 3 minutes per OS, so they stay per-push.

## 17.6 Definition of done (every milestone, doc 16)

1. L0–L4 and L6-CLI green on Linux and Windows; L5 green nightly for every backend the milestone introduced.
2. LoC caps respected, with no new exceptions unless approved.
3. The milestone's own safety tests are in the catalogue and green.
4. L7 checklist run on at least one real game per engine touched; results recorded.
5. Docs updated: contract changes noted, open questions closed or moved.
