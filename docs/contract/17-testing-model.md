# 17. Testing model

Normative for 1.1. **History:** draft 3 (2026-11-02) proposed pytest, per-push CI with nightly
tool images, Playwright and refusal-based capture; the owner's CI cost rule, D22 and the 1.0
delivery replaced those, and this revision states what is built. Evidence is the test module.

## 17.1 Principles

1. **No real game data in the repository or in CI.** Every fixture is **synthetic**: generated by a builder at test time, tiny, and deterministic. Freedoom (BSD) is downloaded by the CI real-tools job only.
2. **Fakes before real tools.** Every slot is tested with fake backends. Real third-party tools get smoke tests that run when the tool is present (`third_party/` or a `VIWO_<ID>` override) and skip with the tool named otherwise.
3. **The v1 code was removed, not characterized.** The characterization suite of draft 3 (L2) was dropped when v1 was deleted (prototype A); the intended behaviour is covered by the L1-L4 tests instead (`docs/prototype-a/STATUS.md`).
4. **Every contract rule has a test** that would fail if the rule broke: single writer, reserved dot-folders, routing, failover, determinism, the warnings policy (D22), import direction, licence isolation, declared network use.
5. **Safety is tested, not assumed:** malicious archives, path traversal, pickles, game-folder restore.

## 17.2 Levels

| Level | What | Runs | Gate |
|-------|------|------|------|
| **L0 static** | `ruff format --check`, `ruff check`; **LoC caps** (doc 15, `tools/loc_count.py`, `tests/test_pipeline.py::test_loc_caps`); import-direction lint, GPL/AGPL ⇒ `isolation="subprocess"`, every backend declares `network` (`none`/`download`/`any`) and `parses_untrusted_in_process`, schema validation of `loc_caps.ini`: all in `tests/test_l0_static.py`; schema validation of `distros/*.ini` (`viwo config check`, `tests/test_config.py`) | every CI run, Linux + Windows | blocking |
| **L1 contract / unit** | conformance kit for plugins, slots and backends (`tests/test_conformance_kit.py`, runnable by third-party plugins through `custom_dirs`), OS layers (`tests/test_os_layer.py`); plugin routing (`select_plugins`); ini precedence; identify/carve rules; value types; journal | every CI run | blocking |
| **L2 characterization** | dropped (17.1 #3) | — | — |
| **L3 component** | each plugin against its synthetic fixtures, with fake tools and stdlib backends (one `tests/test_<engine>.py` per plugin, `tests/test_formats.py` for the single-container engines) | every CI run | blocking |
| **L4 matrix** | (a) selection exhaustive over every plugin subset × policy, plus pairwise pipeline runs (`tests/test_mixed.py`, doc 3.6); (b) **slot failover**: every outcome kind through main and spare (`tests/test_core_units.py::test_failover_outcomes`), binder states main-up/down × spare-up/down (`tests/test_core_units.py`, `tests/test_config.py`) | every CI run | blocking |
| **L5 real-tool smoke** | each real backend on its fixture: 7-Zip, unrar, unrpa, UnityPy, AssetStudioModCLI, GDRE, GodotPckTool, repak, retoc, vgmstream, Freedoom data (`tests/test_l5_tools.py`, `tests/test_l5_data.py`); tools come from the repository's `third_party/` (the CI job runs `viwo install --all` first) or `VIWO_<ID>` overrides; a missing tool skips with its name and the install command | the CI real-tools job (major tags, by hand); locally with `VIWO_L5=1` | blocking |
| **L6 end-to-end** | CLI: `info` / `detect` / `extract` → run record → **re-run gives an identical workspace** (`tests/test_pipeline.py`, `tests/test_cli.py`); HTTP routes through the job adapter (`tests/test_server.py`, `tests/test_api_routes.py`, `tests/test_api_capture.py`, `tests/test_settings.py`); **web UI smoke in a real browser** (`tests/test_ui_smoke.py` + `tests/ui/smoke.mjs`: headless Edge/Chromium over the DevTools protocol; every view, extraction, cleanup, settings apply, SORT keys, theme switch; skipped when no Chromium binary or Node is found); UI style boundary lint (`tests/test_ui_lint.py`) | every CI run (CLI/HTTP/lint); the browser smoke where a browser exists | blocking |
| **L7 manual acceptance** | real games owned by the tester, run locally only, from the `sqc/` checklist (147 checks, P0 subset) and `tools/integration_games.py` over `Test-games/` (`sqc/games.md`). Results are recorded as numbers and run records, **never the assets** | at each milestone exit, by the owner | sign-off |

## 17.3 Safety test catalogue (part of L1/L3)

| Test | Expectation | Where |
|------|-------------|-------|
| zip/tar member with `../` or an absolute path | rejected; nothing written outside dest | `tests/test_pipeline.py`, `tests/test_formats.py`, `tests/test_thirdparty.py` |
| symlink inside an archive pointing outside | not followed: tar links are filtered (`safe_tar_members`); zip entries are always written as plain files | `tests/test_pipeline.py`, `tests/test_conformance_kit.py` |
| RPA whose pickled index contains a `__reduce__` payload | **no code runs**; the archive is reported as corrupt/unsupported and the spare runs only as a subprocess | `tests/test_renpy.py::test_malicious_index_never_runs` |
| `.rpyc` files | never unpickled in process: decompiled by unrpyc in a subprocess (`decode.rpyc`) | `tests/test_renpy.py` (fake unrpyc) |
| nesting depth bomb | stops at the depth limit (10), reported | `tests/test_pipeline.py` |
| decompression bomb | bounded: `LIMIT` per stream, `TOTAL` per file (`viwo/core/carve/streams.py`), `max_length` on BSA inflation | `tests/test_carve.py` |
| a plugin hook writes outside its staging folder | the conformance kit's sandbox check fails (before/after file record) | `tests/test_conformance_kit.py` |
| PREPARE pointed at a folder without the workspace marker | refused, nothing deleted | `tests/test_game_integrity.py` |
| any extraction | **game folder file hashes unchanged** before vs after | every plugin test, `tests/test_game_integrity.py` |
| cross-origin `text/plain` POST, missing token, non-JSON body, foreign Host header, oversized body | 403 / 415 / 413, no side effect | `tests/test_server.py` |
| tar member with `..`, absolute path, device file, or link outside | rejected by the extraction filter | `tests/test_pipeline.py` |
| a capture session killed midway | the next startup finishes RESTORE; game folder hashes identical; a damaged journal restores what it can | `tests/test_capture.py` |
| a game folder with anti-cheat markers, an online title, a sensitive plugin | **warnings and one confirmation, never a refusal** (D22) | `tests/test_capture.py::test_feature_switch_confirmation_and_warnings` |
| `/preview/` and `/api/*` path traversal | 404 / error | `tests/test_server.py` |

## 17.4 Fixtures

| Builder | Produces | Where |
|---------|----------|-------|
| `make_zip/tar/rar`, `make_game` | archives, nested ones, traversal members, a loose game tree | `tests/helpers.py` |
| `make_rpa` | RPA-3 with a safe index, plus the malicious-index variant | `tests/test_renpy.py` |
| `make_pck`, `embed` | Godot PCK, raw or appended to a dummy executable | `tests/test_godot.py` |
| `make_pak`, `key_exe` | tiny pak and an executable carrying a key (fake repak for L3; real repak builds paks in L5) | `tests/test_unreal.py` |
| Unity | a stateful fake UnityPy and a fake AssetStudio; no UnityFS writer exists, real files are an L7 item | `tests/test_unity.py` |
| `make_wad`, `rgssad_*`, `encrypt_mv`, `xp3`, `asar`, `vpk`, `bsa`, `ba2` | one builder per custom-engine container | `tests/test_doom.py`, `tests/test_rpgmaker.py`, `tests/test_formats.py` |
| marker-only game trees and mixed folders | every engine's markers, several engines in one tree | `tests/test_mixed.py` |

Fixture data is generated into a temporary folder at test time. No binary fixture is committed.

## 17.4b Terms-of-service-sensitive cases: independent operator

Tests that touch terms-of-service-sensitive targets (the Overwatch plugin against a real
install) are **run by an independent operator**, never by the project's CI or maintainers.

| Aspect | Rule |
|--------|------|
| Marking | a plugin whose real-data use is terms-of-service-sensitive declares `tos_sensitive=True` in its manifest |
| Project CI | runs only **fake-tool / synthetic** tests for such plugins (L1-L4, `tests/test_overwatch.py`) |
| Operator receives | a pinned build, the plugin, the `sqc/` checks marked OPERATOR and the run-record schema |
| Operator returns | run records, metrics and pass/fail per check, **never extracted assets**, plus the tool and game build versions used |
| Operator's environment | their own machine and their own licensed copy; offline where the game allows it |
| Policies | none in the code (D22): the operator, like every user, sees the reminder and carries the responsibility |
| Records | operator reports are stored as test evidence under `docs/evidence/<plugin>/<date>.md`, without assets |

## 17.5 Tooling and environment

- **Python:** 3.11 minimum (`requires-python`); CI tests 3.11 and 3.13.
- **Runner:** the standard library `unittest` (`python -m unittest discover -s tests -t .`); no test framework is installed. Levels are selected by environment variables, not markers: `VIWO_L5=1` for real tools, `VIWO_UI=0` to skip the browser smoke, `VIWO_FREEDOOM` for the data test.
- **CI:** GitHub Actions, `ubuntu-latest` + `windows-latest` × Python 3.11/3.13 for L0-L4 and L6; a real-tools job (both OSes, Python 3.13) that runs `viwo install --all` and then the suite with `VIWO_L5=1`. **Cost rule (owner):** CI runs only when a `vN.0.0` tag is pushed or when started by hand; there is no per-push run and no nightly. Everything runs locally before every commit (`tools/version.py commit`).
- **Coverage floors (ratchet):** `coverage` runs the L0-L4 suite in CI; `tools/coverage_check.py` fails the job when a layer drops below its floor. The draft 3 targets were contracts + core ≥ 90 %, plugins ≥ 80 %, OS layers ≥ 75 %. The floors in the script are the measured values of 1.1 minus 2 points where the target was not yet reached; they only move up, with the test that earned the raise.
- **Speed budget:** L0-L4 and the CLI/HTTP end-to-end tests under 3 minutes per OS; the browser smoke adds about 2 minutes where it runs.

## 17.6 Definition of done (every milestone, doc 16)

1. L0-L4 and L6 green on Linux and Windows (locally before the commit; on CI for the major tag); L5 green in the real-tools job for every backend the milestone introduced.
2. LoC caps respected, with no new exceptions unless approved (doc 15.5).
3. The milestone's own safety tests are in the catalogue and green.
4. L7: the `sqc/` P0 subset and `tools/integration_games.py` run on at least one real game per engine touched; results recorded.
5. Docs updated: contract changes noted with a History line, open questions closed or moved; `docs/contract/CONFORMANCE.md` regenerated.
